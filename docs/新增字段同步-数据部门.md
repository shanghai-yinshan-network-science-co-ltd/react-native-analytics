## B. 单条 log：`collector_event`

### 如何识别

```sql
-- 伪 SQL
WHERE action_type = 'collector_event'
```

- 业务调用 `saveNodeLog(eventName)` 才产生
- 一条独立行为日志，字段摊平在该 log 对象上（与 `action_type`、`event_name` 同级）
- **不要**把这些字段当成设备包字段，也 **不要** 期望 click / page 等其它 log 带这些字段

### 已有 log 信封（沿用老列即可）

| 字段名 | 说明 |
| --- | --- |
| `action_type` | 固定 `collector_event` |
| `event_name` | 业务传入的节点名；未传则为 `collector_event` |
| `log_time` / `log_time_z` | 日志时间 |
| `start_time` / `start_time_z` | 开始时间 |
| `log_source` | `rn` |
| `page_id` | 当前页（Android 有；iOS 可能为空） |
| `log_id` / `user_uuid` | 原有逻辑 |

### 本条 log 新增 / 需要落表的字段

时间：iOS `yyyy-MM-dd HH:mm:ss`；Android 部分带毫秒 `yyyy-MM-dd HH:mm:ss.SSS`。时间戳为毫秒。  
耗时：整数，单位毫秒。  
布尔：JSON `true/false`。  
空值：采不到时多为 `""`，不是缺 key（客户端会带上 key）。

## D. 注意点（改表 / 写 SQL 时）

1. **两套 `client_id` / `collect_time`**：设备包外层有一份；`collector_event` 这条 log 上也有一份。不要只落一张表就当成全量。
2. **不要用设备包字段去关联每一条行为 log 的 env/vs/battery**。那些只在 `collector_event` 上。
3. 设备包 `battery_is_charging` 与单条 log `battery_charging` **不是同一个 key**。
4. 设备包 `is_clone` / `is_emulator` / `is_hook` 与单条 log `env_is_clone` / `env_is_emulator` / `env_is_hook` **不是同一个 key**。
5. JSON 数组字段（`collector_items`、`vs_current_audio_outputs`、`sr_display_infos`）建议 `STRING` 存原文，解析时再 `get_json_object` / `json_tuple`。
6. 服务端建议补：`server_time`、`storage_time`、`outer_net_ip`。
